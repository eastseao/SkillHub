# 决策路由引擎 v2.0

## 任务分类速查

收到用户请求后，第一时间判断任务类型，走对应路径：

```
用户说"帮我写..." → 创作类
用户说"分析..." → 分析类
用户说"改..." → 优化类
用户说"给我几个..." → 选题类
用户说"帮我看下..." → 阅读类
```

## 创作类工作流

**触发词**：写一章节、写一段、写个开头、写个高潮、写完整章、写完这个故事

```
第一步：识别创作类型
├── 写章节正文 → 走「章节创作流程」
├── 写完整大纲 → 走「大纲生成流程」
├── 写具体场景 → 走「场景创作流程」
└── 写选题/标题 → 走「选题标题流程」

第二步：提取任务要素（强制提取，缺一不可）
├── 题材/类型
├── 核心冲突
├── 主角基本设定（姓名/性别/核心能力/当前处境）
├── 目标读者情绪
└── 篇幅要求

第三步：选择情绪配方（见 emotion-designer.md）
第四步：按流程执行
```

### 章节创作流程

```
1. 判断章节类型
   ├── 开篇章 → 检查是否满足「黄金三章」要求
   ├── 高潮章 → 检查压迫值是否足够高
   ├── 过渡章 → 检查是否埋下下一个冲突钩子
   └── 结尾章 → 检查断章位置是否在高看点

2. 产出内容（直接输出，不说"好的"）

3. 章节质量门检验
   ├── 每300字有事件？
   ├── 冲突在升级？
   ├── 结尾钩子够强？
   └── 爽点密度达标？
```

### 大纲生成流程

```
1. 确定篇幅（五幕剧还是多 Arc）
2. 确定核心爽点（全文最大爽点是什么，先写出来）
3. 确定 Boss 层级（有多少个阶段性反派）
4. 生成章节序列（按 emotion-designer.md 的情绪曲线规划）
5. 检查冲突密度（每3-5章一个小高潮，每10章一个大高潮）
```

## 分析类工作流

**触发词**：分析一下、看看这个、帮我评估、节奏怎么样、冲突够不够

```
1. 阅读内容（如有附件先读附件）
2. 按「爽导式研究」框架分析：
   ├── 冲突够不够强烈？
   ├── 节奏有没有拖沓？
   ├── 钩子够不够强？
   ├── 爽点够不够爆？
   ├── 压迫值够不够高？
   └── 描写占比超标了吗？
3. 给结论（直接说问题，不说"总体来说"）
4. 给修复方案（可执行的改动指令）
```

## 优化类工作流

**触发词**：改一改、改得更好、70分提到90、优化一下、润色

```
1. 识别优化类型
   ├── 压迫值不够 → 叠加冲突
   ├── 爽点不够 → 增加反转或身份曝光
   ├── 钩子太弱 → 换断章位置或加悬念
   └── 节奏拖 → 删除描写，压缩过渡
2. 给出改动（直接改，不说"可以这样改"）
3. 验证改动后是否引入新问题
```

## 选题标题工作流

**触发词**：给我几个选题、想个标题、爆款标题、取名字

```
选题：
1. 找极端对立（职业/身份/世界的极端组合）
2. 找高情绪词（逆袭/重生/穿越/马甲/黑化/团宠）
3. 验证冲突密度（这个组合能撑多少章冲突）
4. 输出3个，每个附一句话核心冲突描述

标题：
1. 找极端对比词（废物→天才、穷鬼→首富、舔狗→被倒追）
2. 叠加情绪词（打脸/逆袭/绝地反击）
3. 控制在18字以内
4. 输出10个，强弱排序
```

## 场景决策树

```
当前场景需要哪种节奏？

有高潮任务？
├── 否 → 检查是否需要埋钩子
│        ├── 需要埋钩子 → 在场景末尾1/10处埋悬念
│        └── 不需要 → 场景结束，检查下一个场景
└── 是 → 检查场景类型
         ├── 打脸/反击 → 压迫→反转→身份曝光三连
         ├── 身份揭露 → 前2/3误导 → 最后1/3真相
         ├── 升级/获宝 → 争夺过程（每300字升级一次）
         └── 情感爆发 → 积累→误解→爆发→断章或和解
```
