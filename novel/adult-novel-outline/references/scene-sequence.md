# 长篇场景序列设计师 v2.0

## 核心职责

管理10章以上的多场景、多视角、多线程叙事。核心矛盾：如何在复杂结构中保持每章都有爆点，不让读者在中段弃文。

## 场景类型体系

### 五种场景类型

| 场景类型 | 英文 | 功能 | 出现频率 | 必须满足 |
|---------|------|------|---------|---------|
| **行动场景** | Action | 推动主线，制造冲突 | 占总量60%+ | 有对手、有风险 |
| **反应场景** | Reaction | 情绪释放、内心独白 | 占总量15% | 有反思、有变化 |
| **准备场景** | Preparation | 积蓄力量、布局 | 占总量15% | 有障碍、有时间压力 |
| **过渡场景** | Transition | 场景切换、视角转换 | 占总量5% | 快进、不断章在高潮 |
| **高潮场景** | Climax | 核心爽点爆发 | 每Arc至少1次 | 有代价、有转折 |

**黄金比例**：行动场景（60）+ 反应场景（15）+ 准备场景（15）+ 过渡场景（5）+ 高潮场景（每个Arc 1-2次）≈ 100

## 多视角管理规则

### 视角切换时机

```
换视角的信号：
- 上一视角已无冲突可写
- 需要展示反派/盟友视角以构建信息差
- 时间并行：同一时间不同空间发生的事
- 情绪节奏需要：主角受压时切到反派得意，反派打脸后切回主角

禁止的切换：
- 高潮进行中切换（打断爽点节奏）
- 情绪未平复时切换（读者还在等待结果）
```

### POV 分布公式

```
主角 POV 占比 ≥ 60%
核心配角 POV = 20-30%（每个配角单独成 POV 线）
反派 POV = 10-15%（建立压迫可信度）
其他 = 5%（工具人视角，用于信息传递）
```

## 多线程管理

### 线程定义

一条线程 = 一个核心冲突线，从建立到解决。

**示例**：
- 线程A：主角与反派的职场竞争线（从入职到升职对决）
- 线程B：主角的身世之谜线（从怀疑到真相揭露）
- 线程C：主角与男/女主的感情线（从误解到相守）
- 线程D：主角与家人的和解线（从隔阂到团圆）

### 线程激活节奏

```
每 3-5 章：至少有 2 条线程同时激活
每 7-10 章：至少有 1 条线程解决或阶段性突破
每 15-20 章：开启新线程（防止旧线程消耗殆尽）

并行线程上限：不超过 4 条主线同时激活
```

### 线程切换原则

```
同一章内最多切换 2 次场景/视角
切换时保留上一场景的钩子
切换到新场景后，前 3 句必须承接上文悬念
```

## 场景序列设计流程

### 第一步：建立 Arc 结构

```
整个故事 = 1个大Arc或N个中Arc串联

每个 Arc 的结构：
[Arc Name]
├─ Arc 目标（主角在这个Arc要达成什么）
├─ Arc Boss（这个Arc的主要对立力量）
├─ Arc 爽点（这个Arc的核心爆点是什么）
├─ Arc 时长（多少章）
└─ Arc 结尾钩子（Arc 结束时留下什么悬念）
```

### 第二步：拆解章节任务

```
每章任务卡：
├─ 章节目标：这章要推进什么？
├─ 冲突密度：这一章要有几个冲突点？
├─ POV：这章用谁的角度写？
├─ 爽点时机：这章的爽点放哪个位置？
└─ 章节钩子：这章结尾留什么悬念？
```

### 第三步：检查节奏分布

```
用「每章事件数」检验节奏：
- 每章至少 2 个事件（冲突/决定/反转）
- 每3章至少1个爽点
- 每章必须有钩子

用「压迫值走势」检验节奏：
整体曲线应该是波浪式上升，不是一条平线或纯上升线
```

## 场景内节奏控制

### 单场景四段式

```
第1段（25%）：建立场景 + 引入冲突
第2段（25%）：冲突升级 + 阻碍出现
第3段（25%）：关键转折 + 意外介入
第4段（25%）：爽点 + 场景钩子
```

### 场景内换节奏信号

```
节奏变慢的信号：主角开始大量内心独白、描写环境、回忆
节奏变快的信号：短句增多、对话变快、动作变密
节奏切换时机：在情绪高点或低点切换，不要在中间切换
```

## 常见结构问题修复

| 问题 | 症状 | 修复方案 |
|------|------|---------|
| 中段弃读者 | 10-20章明显掉订阅 | 在10章/20章设置大爽点 |
| 视角混乱 | 读者不知道谁在说 | 限制 POV 数量，每章最多2个视角 |
| 线程断裂 | 某条线程消失10章以上 | 每5章至少提及一次活跃线程 |
| 高潮密度不足 | 全程平推，没有爆点 | 用decision-tree重新规划爽点位置 |
| 场景同质化 | 每次冲突都是同一套路 | 至少准备3种不同冲突类型轮换 |
